# REQ — visual-upgrade

## 1 概述
### 1.1 需求背景 [冻结]
v2.3.0 之后，站点能发布、能恢复，但从没问过「谁用不了它」。v2.4.0 Phase 0 的基线审计（生产公开页面；桌面、iPad、Android、iPhone、320px、200% 缩放；axe、键盘、代码审读）找到两处阻断：纯键盘用户打不开功能菜单，因而无法搜索、无法切换语言；卡片标签与首页照片的标题只在悬停时出现，三种触屏设备上始终看不见。另有一批严重项：对比度差一点（60% 墨色 4.37:1），英文页面上读屏念中文，搜索对话框不管焦点，320px 下横向溢出，列表页没有 `h1`，固定且自动隐藏的头部在放大时占去四成视口。

同时，美学论文「活手稿」经 Phase 1 审视后不自洽：它开篇要精神、后文开出摹形的道具；要每一笔深思熟虑，又要随机；以效果求「气韵」，恰与留白相反；它规定的实现手法（组件内联样式）盖掉了键盘焦点环。Phase 1 与 Jason 逐层讨论后，论文重写为《临湖》。站点访问量很低；做无障碍是因为照顾不同的人本身重要，精力有限，所以标准取 AA、验证深度有界。

### 1.2 范围
- 做：
  - 公开页面与后台 `/admin` 满足 WCAG 2.2 AA
  - 公开页面按《临湖》重做：首页（门与一窗主景）、列表页（目录；视觉为照片网格）、文章页（手卷三段、折叠目录、尾纸与终止符）、导航、搜索与语言切换、关于页、404
  - 关于页进数据库、以 Markdown 撰写，可在后台编辑；`next-mdx-remote` 移除
  - React Compiler 的三条 hook 规则恢复为错误
  - 无障碍与美学中可机器判定的部分进闸门
- 明确不做：
  - 暗色模式
  - 逐条人工核对全部成功准则；NVDA / TalkBack / VoiceOver 逐一测试
  - 减少动画偏好（SC 2.3.3，AAA）——《临湖》规定页面自己从不动，残余的动效都由读者触发
  - 后台的写作体验改进（Jason 尚无真实写作中的痛点，出现后再立项）
  - 路由、缓存、发布流程的结构改动；支持的语言集合；内容多语言（关于页除外）

## 2 上下文图
访客（键盘、触屏、读屏、放大，任意组合）→ Cloudflare → nginx → 本应用 → Supabase。维护者在 Mac、iPhone、iPad 的浏览器里打开 `/admin`，经 Supabase Auth 登录，编辑内容与关于页。闸门（GitHub Actions）对一个运行中的实例跑无障碍与美学检查。

## 3 用例
- 视障访客用 VoiceOver 打开一篇中文文章的英文地址：读屏用中文语音念正文，用英文念界面。
- 只用键盘的访客：打开搜索、输入、选中结果、按 Esc 回到原处；切换语言；翻看相册。
- iPad / Android 访客：在首页与列表页看到每篇的标签与日期，不需要悬停。
- 放大到 200% 或在 320px 宽的手机上：不横向滚动，焦点不被挡住。
- 访客第一次到首页：五秒内知道这是一个什么样的人——门、一张照片、三段文字。
- 维护者在 iPad 上改关于页的中文版并保存；法语访客看到英文版。
- 维护者只用键盘在后台写一篇、存草稿、发布。

## 5 功能需求

### 5.1 无障碍底线（F1）
- 规则：标准是 WCAG 2.2 AA 的全部 A 与 AA 成功准则。验证深度有界：自动检查（axe）+ 键盘走核心任务 + Jason 真机走同样任务；后台另做逐页人工审计。
- 设备覆盖按等价类，不按型号：渲染引擎（Blink、WebKit）× 宽度（320、手机、平板、桌面）× 输入（能悬停 / 不能悬停、键盘）。
- 核心任务：读一篇文章；打开搜索、输入、打开结果、关闭后焦点回到触发处；切换语言；打开相册查看器、翻页、关闭；后台：登录、新建一篇、存草稿、发布。
- 语言：页面的 `lang` 取自 URL；正文容器的 `lang` 取自条目的写作语言；界面上的可访问名称取自当前语言的文案，不写死任何语言；格言标 `lang="la"`。
- 验收判据：
  - §5.1-a 每一种公开页面模板（首页、四个列表页、四种详情页、标签页、关于页、404、打开状态的搜索对话框与相册查看器），在桌面 Blink、触屏 WebKit、触屏 Blink、320px 四种环境下，axe（WCAG 2.0 / 2.1 / 2.2 的 A 与 AA 规则）报 0 个违例。
  - §5.1-b 后台四个页面模板（登录、总览、列表、编辑器）axe 报 0 个违例。
  - §5.1-c 核心任务（公开部分）在桌面环境中只用键盘能完成，且每一步焦点可见；对话框打开时焦点移入、Tab 不离开、Esc 关闭后焦点回到触发它的元素。
  - §5.1-d 在不能悬停的环境中，首页与列表页上每一篇的标题、日期、标签都可见（非透明、非裁切、在视口内可滚动到）。
  - §5.1-e 在 320px 宽的环境中，任何公开页面 `scrollWidth` 不大于视口宽度。
  - §5.1-f 英文页面上，界面元素（非内容标题）的可访问名称不含中文；详情页正文容器的 `lang` 等于条目的写作语言。
  - §5.1-g 每个公开页面恰有一个 `h1`，标题层级不跳级。
  - §5.1-h 后台核心任务只用键盘能完成（Phase 4 人工走一遍，结果记入 TRACK）。
  - §5.1-i 在平板宽度与 200% 放大下，任何公开页面不横向滚动；把行高、段距、字距、词距放大到 1.4.12 规定的值后，没有文字被截断或重叠。

### 5.2 《临湖》落地（F2）
- 规则：公开页面遵守 `docs/aesthetic-thesis.md` 全文。下列判据是其中可机器判定的部分；其余由 Jason 按论文「七、审查顺序」逐模板验收。
- 首页的框景取每类最新一篇（视觉取最新一组的封面照片）；空类型的窗不显示，不补位。
- 文章页：引首只有日期、标题、导语与封面；元数据（写于、标签、语言）在尾纸；有 3 个及以上二级标题的文章，在引首之后有一个默认折叠的目录，少于 3 个则没有目录。尾纸末行是「回到顶部」（有目录时另有展开目录的「目录」），终止符在这一行的末尾。
- 导航不跟随读者；搜索在页面任何位置可用 ⌘K / Ctrl+K 打开，关闭后焦点回到读者原处。
- 验收判据：
  - §5.2-a 任一公开页面上，计算样式里用到朱砂色（文字、背景、边框、描边任一）的元素只有终止符，且至多一个。
  - §5.2-b 任一公开页面加载完成后、不做任何操作时，页面上没有正在运行的动画或过渡。
  - §5.2-c 任一公开页面上没有元素带投影或文字阴影。
  - §5.2-d 使用 Cormorant Garamond 的元素只在首页的门里。
  - §5.2-e 导航不固定：滚动后它随页面离开视口。
  - §5.2-f 首页与列表页上不出现文章或项目的封面图。
  - §5.2-g 首页的四扇窗分别是四类内容各自最新的一篇；某类为空时该窗不出现（单元测试，假数据）。
  - §5.2-h 详情页的尾纸含写于日期、标签、语言，并以终止符结束；有目录的文章，目录默认折叠且以键盘可展开。
  - §5.2-i Jason 按审查顺序逐模板签收（Phase 4，结果记入 TRACK）。

### 5.3 关于页进库（F3）
- 规则：关于页是数据库里的内容，正文为 Markdown（与其他内容同一渲染器、同一净化规则），每种站点语言可有一份。请求的语言没有时回退：请求语言 → 英文 → 任意一份。后台可新建、编辑、发布每种语言的版本（纯文字，不上传图片）。现有五份仓库文件的内容迁入后删除，排版随《临湖》重做；格言的释义放在关于页。
- 验收判据：
  - §5.3-a 有某语言版本时显示该版本；没有时显示英文；英文也没有时显示任意一份（单元测试，假数据）。
  - §5.3-b 在后台保存关于页后，下一次匿名访问即显示新内容——包括经回退显示该版本的其他语言；新增一种语言的版本后，该语言的下一次访问即显示它。
  - §5.3-c 依赖里没有 `next-mdx-remote`，仓库里没有 `src/content/pages/`。

### 5.4 hook 规则（F4）
- 验收判据：
  - §5.4-a `eslint.config.mjs` 不再降级 `react-hooks/set-state-in-effect`、`immutability`、`static-components`；`npm run lint` 报 0 个错误。

### 5.5 闸门（F5）
- 规则：§5.1-a、c、d、e、f、g、i，§5.2-a 至 h 与 §5.3-b 中能对运行中实例判定的，随每次推送在闸门里运行，对着带有代表性内容的实例（不能是空页面——空页面上的 0 违例不证明任何事）：每次运行临时拉起一个 Docker 数据库、填入合成内容，检查完即删除；不对生产运行，不用真实内容。后台审计（§5.1-b、§5.1-h）用同一套环境。检查自身须证明不空转：在分支上故意引入一处违例，闸门变红一次。
- 验收判据：
  - §5.5-a 闸门日志里，无障碍与美学检查覆盖的页面数与环境数非零，且与 §5.1-a 列出的模板一致。
  - §5.5-b 故意引入的一处违例（如一个没有标签的按钮）让闸门失败（记录运行号）。

## 6 其他需求
- 可缓存：公开页面保持可缓存，规则与证据方式见项目 `CLAUDE.md`。新交互不得让公开页面读 cookie 或请求头。
- CSP 不放宽：新字体、样式、脚本自托管。
- routing-slimdown REQ §6（外观与 `<head>` 不变）与其验收 §6-a 本版退役；`<head>` 中的元数据（标题、描述、分享图、规范地址、语言替代链接）仍须正确，由既有的其他判据守护。
- The Floor：后台审计只在本地实例、合成内容上进行；生产后台的会话与草稿不进入任何审计工具。
