# REQ — content-publishing

## 1 概述
### 1.1 需求背景 [冻结]
2026-09-21 的全面扫描与 v2.2.0 的收尾把这些事实摆上台面。自 2026-03 切换到 Supabase 后，站上只有闪念能从后台发布；专栏、实验室、视觉要到 Supabase 控制台手写 SQL，半年间没有发过一篇新内容。2026-09-22 第一次真正使用后台，发布按钮点两次就撞上 slug 唯一约束、弹出框架的报错页。正文以 MDX 在服务端编译执行，管理员密码一旦泄露即是服务器上的代码执行，而容器以 root 运行。此外一组小债：五个生产依赖有安全通告；出错时访客看到框架原始画面；Safari 上语言选择只记七天；跳转链接落点在导航之前；四种内容类型的仓库代码写了四遍；内容没有任何备份；keepalive 的告警写进无人读的文件。维护者只有 Jason 一人，写作可能发生在 Mac、iPhone、iPad mini 上。

### 1.2 范围
- 做：
  - 生产依赖升到无安全通告的版本，含 Next 16
  - 正文只当 Markdown 渲染，容器不以 root 运行
  - 五种内容（专栏、闪念、实验室、视觉、关于页）都能在后台新建、编辑、存草稿、发布、撤回，含图片上传；手机浏览器可用
  - 出错与不存在的地址给访客站点自己的页面与正确的状态码
  - 一组安全加固（镜像、响应头、cookie、三个 XSS 汇点、规范域名、注册开关）
  - 内容每日备份到 VPS；keepalive、备份、站点可达三件事有人被告知
  - 手动选择的语言在 Safari 上也记一年
  - 跳转链接真正跳过导航
  - 四种内容类型的重复代码合一，行为不变；补齐回退路径的测试
- 明确不做：
  - 公开页面视觉与交互的任何改动 → v2.4.0
  - 所见即所得编辑器；本地文件 + 命令行发布；内容离开 Supabase
  - 多作者、权限分级、评论、内容版本历史、定时发布、改 slug 后旧地址的重定向
  - 改变支持的语言集合；关于页以外的多语言内容
  - 删除条目时连带删除存储桶里的文件（现状保留）；搬迁 `public/images/` 里已有的图片

### 1.4 术语
- 内容条目：`content_items` 的一行；类型为专栏 `post`、闪念 `note`、实验室 `project`、视觉 `gallery`，本版加关于页。
- 正文：`body_markdown` 列，纯 Markdown。
- 写作语言：`locale` 列——这条正文用什么语言写，不是站点语言。内容单源：每个站点语言显示同一条目。
- 发布入口：`/admin` 下的编辑器。
- 存储桶：Supabase Storage 的公开桶，本版起所有新图片的存放处；已在 `public/images/` 里的图片留在原处。
- 死人开关：VPS 之外的监控服务，期待按周期收到「报平安」；到点没收到就通知维护者。

## 2 上下文图
维护者在 Mac、iPhone 或 iPad 的浏览器里打开 `/admin` → 本应用 → Supabase（Postgres 存正文与元数据，Storage 存图片，Auth 认管理员）。访客与搜索引擎 → Cloudflare → nginx → 本应用 → Supabase。VPS 上的 cron 定时跑 keepalive（向 Supabase REST 发一个查询）与备份（`pg_dump` + 存储桶同步 → VPS 数据目录），两者成功后向死人开关服务报平安；死人开关另从外部探测站点可达；任一缺席即通知维护者。GitHub 上 `main` 的合并触发部署。

## 3 用例
- 维护者在手机上写一条闪念，配一张刚拍的照片，发布。
- 维护者在 Mac 上用惯用编辑器写完长文，贴进后台，上传封面与插图，看预览，存草稿，改几轮后发布。
- 维护者上传一组照片建相册，排顺序，写说明，选封面。
- 维护者改关于页某一种语言的一句措辞。
- 维护者发现一篇文章有错，撤回为草稿，改好再发。
- 访客打开一个不存在的文章地址，或恰逢数据库抖动，看到的是站点自己的页面。
- Supabase 项目被暂停，或 VPS 上的 cron 停了，维护者当天收到通知。
- Supabase 项目丢失，从 VPS 上的备份恢复。

## 5 功能需求

### 5.1 依赖升级（F1）
- 规则：`npm audit --omit=dev` 零通告；`next` 升到 16 的当前稳定版并钉精确版本；升级后上一版的全部验收判据仍成立，`<head>` 唯一允许的差异是 `viewport` 属性的顺序（相应修订 routing-slimdown REQ §6）。闸门的每一步在新版本下都真的在检查——不因命令换名而变成空转。
- 验收判据：
  - §5.1-a `npm audit --omit=dev` 报 0 个漏洞。
  - §5.1-b routing-slimdown 的单元与运行时验收全绿（`<head>` 基线按裁定更新后）。
  - §5.1-c 故意引入一个 lint 错误的分支，闸门在 lint 步骤失败。

### 5.2 正文渲染（F2）
- 规则：正文是 Markdown——CommonMark + GFM（表格、删除线、任务列表、自动链接）+ 数学（`$…$`、`$$…$$`，KaTeX 输出）。原始 HTML、JSX、`import`/`export`、`{…}` 表达式一律不执行、不进入 DOM 结构，原样作为文字显示。五种内容与后台预览用同一个渲染器。
- 图片排版规则：一个段落里只有图片（一张或多张）时，多张并排显示，图片的 `title` 文字作为图注——排版是渲染器的事，正文里不写布局。
- 迁移：生产上唯一使用了 JSX 的正文是一篇专栏（三张并排带图注的插图，用 `<div style={{…}}>` 与 `<img>` 写成），按上一条规则改写为 Markdown；其余正文只有公式，不需改动。改写后每条正文经新渲染器渲染，与旧渲染结果比对。
- 硬错误：渲染器抛错 → 该页走 §5.4 的错误页，不是空白或框架画面。
- 容器：应用进程以非 root 用户运行。
- 验收判据：
  - §5.2-a 含 `<script>alert(1)</script>`、`{1+1}`、`import x from 'y'`、`<Component />` 的正文渲染后：HTML 中没有 `<script>` 元素、没有 `2`、四段文字原样可见。
  - §5.2-b GFM 表格、删除线、任务列表、自动链接，以及行内与块级公式，渲染为对应的 HTML 与 KaTeX 输出；一段三张带 `title` 的图片渲染为并排的三个带图注的图。
  - §5.2-c 生产上全部已发布正文在新渲染器下无错误，逐条比对的差异均已处置（Phase 4，对生产数据）。
  - §5.2-d 运行中的容器内 `id -u` 不为 0。

### 5.3 发布入口（F3）
- 规则 1 —— 范围：五种内容都能在 `/admin` 新建、编辑、存草稿、发布、撤回为草稿。每种类型可编辑的字段 = `content_items` 的列 + 该类型的关联表（`gallery_images`、`project_links`）+ `extra_metadata` 里映射函数已读取的键；以表结构与映射函数为准，不在此重抄。
- 规则 2 —— 关于页：可以有任意几种站点语言的版本，每种最多一份；访客请求的语言没有版本时依次回退到英文、再到任意一份，永不空页（与 UI 字串的回退规则同构）；`/about` 不再读仓库文件，现有五种语言的正文迁入。
- 规则 3 —— 幂等：同一（类型、写作语言、slug）再次保存即更新，不新建；提交进行中按钮禁用；重复提交既不产生第二条也不出报错页。
- 规则 4 —— slug：必填，只含小写字母、数字、连字符；改 slug 等于换地址。
- 规则 5 —— 图片：封面与正文插图从设备选择或粘贴上传到存储桶，上传完成即得到公开 URL；插图以 Markdown 图片语法插到光标处。相册一次可选多张，可排序、写替代文字、选封面。接受的格式与单张大小上限住配置，超限或非图片拒绝并提示。
- 规则 6 —— 新鲜度：发布、更新、撤回完成后的下一次访问即反映（routing-slimdown §5.3-b 推及全部类型与关于页）；撤回后详情地址为 404。
- 规则 7 —— 预览：编辑时可看到与公开页面同一渲染器的结果。
- 规则 8 —— 编辑器：纯文本 Markdown 编辑；Mac 与 iOS Safari 是必须顺手的两种环境。
- 硬错误（响亮失败）：校验失败 → 表单原位标出哪一项，已填内容不丢；上传失败 → 提示，正文不丢；数据库错误 → 可重试的提示，不出框架页。
- 验收判据：
  - §5.3-a 对每种类型：新建为草稿（公开不可见）→ 发布（列表与详情可见）→ 编辑标题（变化可见）→ 撤回（列表不见，详情 404）。
  - §5.3-b 同一 slug 连续提交两次，只有一条记录，第二次是更新。
  - §5.3-c 上传一张图片：桶里出现文件，表单得到其 URL，发布后页面显示该图。
  - §5.3-d 在 375px 宽的视口里完成 §5.3-a 全流程（浏览器实测）。
  - §5.3-e 提交一个校验失败的表单，返回后已填内容仍在。
  - §5.3-f 修改关于页某一种语言，该语言的 `/about` 反映，其他语言不变；删掉某一种语言的版本后，该语言的 `/about` 显示英文版。
  - §5.3-g 未登录访问任一编辑路由或上传接口被拒绝；服务端密钥仍只经管理员校验发放（v2.1.3 的守卫测试保持通过）。

### 5.4 失败处理（F4）
- 规则：不存在的 slug → 状态码 404 与站点的 404 页；不为它读库、不留数据缓存，格式不合的 slug 在到达页面之前就被判为不存在；页面缓存条目允许存在，但按时限重新验证、随每次部署清空（框架在保持详情页可缓存时做不到零条目，见 DESIGN §3）；渲染或读库抛错 → 状态码 500 与站点风格的错误页，页面上不出现错误原文；`/api/search-index` 出错 → 500 与通用 JSON，不含数据库错误文本；后台动作出错 → 后台风格的错误页；保存已成功而其后一步失败时，页面说明「已保存」。
- 验收判据：
  - §5.4-a `/en/posts/does-not-exist` 返回 404，正文是站点的 404 页。
  - §5.4-b 数据库不可达时访问首页：返回 500，正文是站点的错误页，不含 `supabase` 字样。
  - §5.4-c 数据库不可达时 `/api/search-index` 的响应不含数据库错误文本。
  - §5.4-d 访问 20 个不存在的 slug 后，数据缓存条目数不随之增长，且没有发出对数据库的查询；格式不合的地址（含大写、下划线、超长）不产生任何缓存条目。

### 5.5 加固（F5）
- 规则：基础镜像为当前 LTS 的 Node，`Dockerfile` 是唯一来源，CI 与之同步；响应头带 CSP 与 HSTS，不带 `x-powered-by`；会话 cookie 带 `Secure`、`HttpOnly`、`SameSite`；三个 XSS 汇点关闭——相册查看器不以 `innerHTML` 拼接不可信文本，JSON-LD 转义 `<`，项目链接保存时只接受 `http(s)`；规范地址与语言替代地址用 `https://www.antelacus.com`。Supabase Auth 的自助注册已关闭、邮箱确认已开启——这是外部系统的状态，代码不保证它，运维文档记下核对位置。
- 验收判据：
  - §5.5-a 运行中的服务：响应头含 CSP 与 HSTS，不含 `x-powered-by`；页面在 CSP 下功能完整（公式样式、相册查看器、搜索）。
  - §5.5-b 保存 `javascript:` 开头的项目链接被拒；标题含 `</script>` 的条目，其页面 JSON-LD 与相册说明中不出现未转义的 `</script>`。
  - §5.5-c 页面的 canonical 与 alternate 均以 `https://www.antelacus.com` 开头。
  - §5.5-d 容器内 Node 主版本等于 `Dockerfile` 声明的版本，且该版本在维护期内。

### 5.6 备份（F6）
- 规则：VPS 上每日一次 `pg_dump`（全库、压缩）加存储桶全部文件同步，落 VPS 数据目录，不再同步到 VPS 之外；保留天数住脚本配置；成功后向死人开关报平安；导出物不进仓库；恢复步骤写在运维文档。
- 验收判据：
  - §5.6-a 备份产物存在且 `pg_restore --list` 可读；同步下来的文件数与存储桶一致。
  - §5.6-b 恢复演练：导入到一个空的数据库，站点指向它能读出内容（上线后一次）。

### 5.7 告警（F7）
- 规则：三个被监控对象——keepalive 定时成功、备份定时成功、站点首页从外部可达；任一缺席或失败即以邮件通知维护者；监控服务不在 VPS 上（选哪家是 DESIGN 的外部约束）。
- 验收判据：
  - §5.7-a 让 keepalive 停跑一个周期，收到通知。
  - §5.7-b 让备份停跑一个周期，收到通知。
  - §5.7-c 停下站点容器数分钟，收到通知（上线后）。

### 5.8 语言记忆（F8）
- 规则：手动切换语言时，cookie 由服务端的响应写入，有效期一年；其余行为同 routing-slimdown §5.2 规则 7。
- 验收判据：§5.8-a 切换请求的响应带 `Set-Cookie: preferred_locale=…`，有效期约一年；页面脚本不再写 `document.cookie`；routing-slimdown §5.2-h 仍全绿。

### 5.9 跳转链接（F9）
- 规则：每页恰有一个 `<main>`，导航在其外；跳转链接的目标是正文起点。
- 验收判据：§5.9-a 公开页与后台页的 HTML 中 `<main>` 恰一个，`<nav>` 不在其内，`#main-content` 在 `<nav>` 之后。

### 5.10 结构合并（F10）
- 规则：行为不变——四种类型的列表、详情、标签、搜索索引、sitemap、分享图与合并前一致；专栏加载器的请求级去重生效；语言前缀的计算只有一处。
- 验收判据：
  - §5.10-a 现有映射函数的快照测试在合并后全部通过。
  - §5.10-b 本地构建的同一组地址，合并前后的 HTML 正文比对无差异（哈希文件名除外）。
  - §5.10-c 一次请求内两次取专栏列表只查一次库。

### 5.11 测试补全（F11）
- 规则：映射函数的回退路径（空 `published_at`、空或数组 `extra_metadata`、无标签）、sitemap 的语言展开与 XML 转义、`getSafeNextPath` 对开放重定向的拒绝，各有断言。
- 验收判据：§5.11-a 上述每条至少一个用例，且删掉被测行为时该用例变红。

## 6 其他需求
- 安全（The Floor 在本版的具体化）：上传与保存接口只对已登录管理员开放；数据库密码只在 VPS 的 `.env`；备份产物含未发布草稿，不离开 VPS，不进提交、PR 描述、日志。
- 可缓存：公开页面继续可缓存，`/admin` 不缓存（routing-slimdown §5.3-a）。
- 可回退：每一批可单独回退；Next 16 批次的回退是回到上一个 tag。
- 外观：不改公开页面的视觉；`<head>` 除 `viewport` 属性顺序与规范域名（§5.5-c）外不变。唯一的例外是删除页面切换时的加载占位动画——它使真 404 不可能（DESIGN §3）。

## 7 对外接口
- 输入——后台表单：字段以表结构为准。空正文、畸形 slug、非白名单图片、超限文件 → 拒绝并原位提示；重复 slug → 视为更新；同一表单重复提交 → 一次生效。
- 输入——正文 Markdown：任何内容都合法，最坏结果是显示为文字（§5.2）。
- 输出——公开页面 HTML：读者是访客、搜索引擎、Cloudflare。
- 输出——存储桶公开 URL：读者是页面与图片优化。
- 输出——备份产物：读者是恢复时的维护者。
- 输出——报平安请求：读者是死人开关服务。
- 外部系统：Supabase Postgres、Storage、Auth；死人开关服务；Cloudflare（响应头经它转发）。
