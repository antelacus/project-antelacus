# REQ — routing-slimdown

## 1 概述
### 1.1 需求背景 [冻结]
2026-09-21 对本站做了一次全面扫描。与本版相关的发现：语言路由的中间件自 2025-09 写成以来从未在生产运行（文件位置不对），于是自动语言跳转、`<html lang>`、后台会话续期都不生效，且任意语言前缀都能打开页面；根布局读 cookie 使全站每次访问都重新渲染、无法缓存；仓库里约五分之一的代码无人引用，几个检查脚本无论如何都通过或都失败；部署前没有任何自动检查。站点的读者是访客和搜索引擎，维护者只有 Jason 一人。

### 1.2 范围
- 做：
  - 部署前的自动闸门

  - 删除无人引用的代码、证明不了任何事的脚本、无人使用的依赖
  - `CLAUDE.md` 与仓库现实一致
- 明确不做：
  - 改变支持的语言集合或翻译内容
  - 内容渲染方式（数据库内容当代码执行的问题 → v2.3.0）
  - 错误页、软 404（不存在的文章返回 200）→ v2.3.0
  - 合并四种内容类型的重复代码
  - 备份、告警
  - Next 16 升级
  - 页面视觉与交互的任何改动

## 2 上下文图
访客与搜索引擎 → Cloudflare → nginx（只接受 Cloudflare）→ 本应用（VPS 上的 Docker 容器）→ Supabase。维护者经 GitHub 推送代码，`main` 上的合并触发到 VPS 的部署；内容经 `/admin` 或 Supabase 控制台写入。

## 3 用例
- 访客从外部链接或直接输入地址进入，希望看到自己语言的页面，并能手动换语言。
- 搜索引擎抓取页面，需要每个内容只有一组规范地址、正确的 `lang`。
- 维护者合并一个改动，希望坏的改动到不了线上。
- 维护者在后台发布一篇笔记，希望它在约定时间内出现在站上。

## 5 功能需求

### 5.1 部署闸门（F1）
- 规则：合入 `main` 的改动在部署之前必须通过 lint、类型检查、全部单元测试、文档预算检查；任一不过，则不部署，线上保持原样。只改文档的提交不触发部署（现状，保留），但同样要过文档预算检查。
- 硬错误：闸门失败 → GitHub 上该次运行标红，部署步骤不执行。
- 验收判据：
  - §5.1-a 故意引入一个类型错误的分支，其闸门运行失败，部署步骤未被执行。
  - §5.1-b 正常改动的运行里，部署步骤在闸门全部通过之后才开始。

### 5.2 语言路由（F2）
对每个进入的地址，按其第一段路径分情形：
- 规则 1 —— 支持的语言：照常提供页面；该页面的 `<html lang>` 等于地址里的语言。
- 规则 2 —— 没有语言前缀（`/`、`/posts`、`/posts/<slug>` 等）：308 到规范地址。选哪个语言，依次看：访客上次手动选择的语言（规则 7）→ 浏览器的 `Accept-Language`（按其给出的顺序取第一个能归到支持语言的）→ `en`。
- 规则 3 —— 语言变体（`/zh-tw/...`、`/en-US/...`）：308 到对应的支持语言，其余路径不变。只有**主标签恰为某个支持语言的基础语言**（`en`、`fr`、`es`、`zh`）的语言标签才算变体；`/essays`、`/friends`、`/english-notes` 这类普通单词不是语言，不得被带到 `/es`、`/fr`、`/en`。
- 规则 4 —— 既不是支持的语言、也不是变体、也不是站内已有的顶级路径：返回真正的 404 状态码；页面是站点风格的英文页（无导航），不依赖 JavaScript 即完整。
- 规则 5 —— 不参与语言路由的地址，原样提供：`/admin`、`/auth`、`/api`、框架与静态资源、`/sitemap.xml`、`/robots.txt`、`/ads.txt`、`/sw.js`，以及分享图 `/og.png` 与 `/<类型>/<slug>/og.png`。分享图的地址已被外部平台缓存，**不得改变**。
- 规则 6 —— `/admin` 与 `/auth` 下的请求会续期登录会话（登录后不因令牌过期而被意外登出）。
- 规则 7 —— 记住手动选择：访客用站内的语言切换时，记下这次选择；之后从无前缀地址进入时优先用它。**只有手动切换才记**——只是打开了一条带语言前缀的链接不算选择。地址里写明的语言永远优先于记住的选择。记下的值若不是支持的语言，当作没有。
- 验收判据：
  - §5.2-a `/en/posts` 返回 200，`<html lang="en">`；`/zh-CN/posts` 返回 200，`<html lang="zh-CN">`。
  - §5.2-b 带 `Accept-Language: fr` 访问 `/posts` → 308 到 `/fr/posts`；不带该头 → 308 到 `/en/posts`。
  - §5.2-c `/zh-tw/posts` → 308 到 `/zh-HK/posts`；`/en-US/about` → 308 到 `/en/about`。
  - §5.2-d `/xx-anything/posts`、`/essays`、`/unknown` → 对原请求直接给出 404 状态码，不经重定向。
  - §5.2-e 语言判定函数：`essays`、`friends`、`english-notes` 均判为「不是语言」；`zh`、`zh-Hans`、`zh-SG` → `zh-CN`；`zh-Hant`、`zh-TW`、`zh-MO` → `zh-HK`；`en-GB` → `en`；`Accept-Language: de, fr;q=0.8` → `fr`；空值 → `en`。
  - §5.2-f `/og.png` 与任一 `/posts/<slug>/og.png` 返回 200、图片类型，且没有发生重定向。
  - §5.2-g `/posts/<已有 slug>` → 308 到 `/<语言>/posts/<同一 slug>`（旧的外部链接继续有效）。
  - §5.2-h 浏览器语言为英文的访客手动切到 `zh-CN` 后访问 `/` → 308 到 `/zh-CN`；同一访客直接打开 `/fr/posts` → 200 且仍是法语页；从未手动切换、只打开过 `/fr/posts` 的访客访问 `/` → 按浏览器语言，不是 `/fr`；记下的值为 `xx` 时访问 `/` → 按浏览器语言。

### 5.3 可缓存与新鲜度（F3）
- 规则：公开的规范地址页面，其响应不得带 `no-store`，同一页面的重复访问不必每次重新渲染。`/admin`、`/auth` 下的页面保持不缓存。新鲜度：经后台保存或发布的笔记，保存完成后的下一次访问就反映在该笔记的详情页、笔记列表、首页与相关标签页上；不经后台、直接改数据库的内容，最长一小时内生效（现状，保留）。
- 验收判据：
  - §5.3-a `/en`、`/en/posts`、一篇文章详情页的响应头不含 `no-store`，同一地址第二次访问命中缓存；`/admin/login` 的响应头含 `no-store`。以**运行中的服务**的响应头为准——构建输出把页面标成静态不算证据。
  - §5.3-b 后台保存动作完成时，笔记相关的缓存已被标记失效（对保存动作的测试可见）；上线后实测：发布一篇测试笔记，随即访问其详情页与笔记列表，二者都已包含它。

### 5.4 瘦身（F4）
- 规则：删除 TD-010 列出的无人引用文件、无人调用的导出、恒过或恒败的脚本及其 `package.json` 入口、无人使用的依赖。离线支持（Service Worker、离线页、从未配置上报地址的性能统计组件）整体移除。
- 约束：已有访客的浏览器里装着当前的 Service Worker。移除后，`/sw.js` 继续存在，但内容换成一个会注销自己并清空其缓存的脚本，且它自身不得被长期缓存——否则老访客永远拿不到新脚本。该脚本约十行，长期保留，不设退役。
- 验收判据：
  - §5.4-a 删除后 lint、类型检查、测试、构建全部通过；`package.json` 里留下的每个脚本运行时都确实检查了某样真实存在的东西。
  - §5.4-b 被删的文件在仓库内无任何引用（由导入关系检查得出，而非按名字搜索）。
  - §5.4-c `/sw.js` 返回 200，其 `Cache-Control` 不含 `immutable` 与长 `max-age`；脚本内容在激活时注销自身并删除其全部缓存；页面不再注册任何 Service Worker。

### 5.5 文档对齐（F5）
- 规则：`CLAUDE.md` 里关于命令、目录、数据流、搜索、中间件、文档命名的每句陈述与仓库一致；能从文件得出的事实指向文件而不复述；行数在预算内。
- 验收判据：§5.5-a `CLAUDE.md` 中出现的每个文件路径与 `npm run` 脚本名都存在。

## 6 其他需求
- 安全：本版不得放宽 v2.1.3 建立的约束——特权数据库客户端只经管理员校验发放（`tests/service-role-guard.test.ts` 保持通过，线上未登录探测保持 0）。
- 可回退：每一批可单独回退；部署出问题时，回退到上一个 tag 即恢复。

## 7 对外接口
- 输入：HTTP 请求的路径与 `Accept-Language` 头。`Accept-Language` 缺失、为空、畸形（非语言标签的任意字符串）时一律按「没有偏好」处理，不报错。只看每一项的语言标签；`;` 之后的参数（`q=0.8`，或任何别的内容）不参与判定，也不使该项作废。
- 输出：HTTP 状态码（200 / 308 / 404）、`Location`、`Cache-Control`、页面的 `<html lang>`。读者是浏览器、Cloudflare 与搜索引擎。
- `sitemap.xml` 里的地址必须全部是规范地址（现状如此，保持）。
